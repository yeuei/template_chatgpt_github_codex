# [ ] PR #<N> 总任务：<一句话描述可关闭的总目标>

> 本文件是累积任务合同：**只增不减**。
> ChatGPT 创建/追加任务；Agent 只根据真实执行状态修改状态标记。

## 状态

```text
[ ] TODO
[~] RUNNING
[x] DONE
[!] BLOCKED
[?] WAITING_USER
[-] SUPERSEDED
```

## 子任务

- [ ] T<N>.1 <子任务 1>
- [ ] T<N>.2 <子任务 2>
- [ ] T<N>.3 <子任务 3>

## 依赖关系

- T<N>.2 依赖：`<无 / T<N>.1>`
- T<N>.3 可与：`<T<N>.1>` 并行

## 验收条件

总任务只有在以下条件同时成立时才能标 `[x]`：

- 所有仍有效子任务已 `[x]`；
- 不存在 `[!] BLOCKED`；
- 不存在 `[?] WAITING_USER`；
- 运行/代码证据支持任务确实完成；
- 没有用 smoke 结果冒充 formal 结果。

如本 PR 启用 Web ↔ Local Agent 配对，另须验证：邀请绑定真实
repository/branch/pr_number，`web_conversation_id` 由 ChatGPT 明确提供，
Local Agent 完成一次 claim/confirm，状态为唯一 `active`，且重复/过期/冲突
不会静默路由。

## 示例

```markdown
# [ ] PR #8 总任务：完成正式数据转换并生成 accepted candidate pool

- [x] T8.1 扫描 Tool-Star 原始数据
- [~] T8.2 Tool-Star 全量转换
- [!] T8.3 Search-R1 正式 source 选择
- [ ] T8.4 生成 accepted candidate pool
- [ ] T8.5 输出统计与 manifest
```

如果旧任务被新任务取代，不删除旧条目：

```markdown
- [-] T8.3 使用旧 Search-R1 source
- [ ] T8.6 重新选择 Search-R1 正式 source 并完成转换
```
