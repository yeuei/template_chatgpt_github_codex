## 6. 验收条件

每个正式模块应明确什么才算 DONE。

示例：

```text
代码存在 ≠ DONE
smoke 通过 ≠ formal DONE
必须满足：
- 正式输入已运行；
- 输出可核验；
- 统计/manifest 已保存；
- 与任务.md 验收标准一致。
```

## 7. 禁止事项

- 不得用旧 runner 的行为反推当前规范；
- 不得用历史 smoke 替代正式运行；
- 不得为填满数量引入不合格数据；
- 不得因为局部 blocker 停止互不依赖任务；
- 不得无理由新增 smoke / benchmark / audit 延迟主线。

## 8. 版本更新原则

如果本规范改变：

```text
直接修改 docs/技术规范.md
```

不要创建：

```text
技术规范_v2.md
技术规范_final.md
```

如需说明一条规则为什么变化，可在 commit message、PR 描述或少量“来源/决策记录”中说明；不要让历史方案重新成为当前真源。
